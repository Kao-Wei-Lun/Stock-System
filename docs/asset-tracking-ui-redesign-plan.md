# 個人資產追蹤 UI / UX 重構規劃 v1.0

**產出時間**：2026-04-21  
**對應功能文件**：`docs/personal-asset-tracking-plan.md`  
**規劃目的**：將目前偏向「資料維護控制台」的資產追蹤頁，重構成「先看資產變化，再查明細，最後做維護」的分層體驗，並以可互動圖表取代總覽頁過度文字化的呈現方式。

---

## 1. 重構背景

目前資產追蹤頁已具備以下能力：

- 資產總覽與績效摘要
- 帳戶、現金流水、交易流水管理
- 對帳快照
- 手動價格覆蓋
- FX 匯率管理
- 調整事件
- CSV 匯入
- Journal 匯入
- 持倉、配置、貢獻排行

問題不在於資料不夠，而在於：

- 主頁同時承載 `總覽 + CRUD 表單 + 匯入 + 例外處理 + 分析`
- 使用者第一眼看不到「資產如何變化」
- 重要資訊和低頻設定共用同一層級
- 總覽頁大多用數字與文字卡片呈現，缺少可探索的互動圖表

這會讓頁面更像後台，而不是每天會打開來看的資產儀表板。

---

## 2. 重構目標

重構後的資產追蹤模組，應在 10 秒內幫使用者回答：

- 目前總資產是多少
- 今天、本週、本月變了多少
- 變化主因是價格、匯率、現金流還是股利
- 哪個帳戶、哪個市場、哪幾檔標的影響最大
- 是否有需要立即處理的對帳差異、報價缺失或資料異常

---

## 3. 設計原則

### 3.1 首頁優先回答變化，不優先顯示表單

使用者進到資產模組後，第一層應先看到結果與原因，而不是先看到各種手動輸入區塊。

### 3.2 核心資料與維護工具分層

- `總覽`：看結果與趨勢
- `持倉與流水`：看明細與來源
- `資料維護`：做手動輸入、匯入、對帳與例外處理

### 3.3 自動可得資料應自動顯示

若系統可直接取得：

- 最新股價
- 最新公開匯率
- 推導後持倉
- 估值結果

則不應再以同等權重要求使用者手動維護，而應將人工覆蓋移到進階區或例外區。

### 3.4 手動功能不直接刪除，而是降級

以下功能仍需保留，但不應佔用首頁：

- 手動價格覆蓋
- 手動 FX 覆蓋
- 調整事件
- 批次重算

因為它們仍是資料失敗、企業行為或特殊例外時的重要備援機制。

---

## 4. 新的資訊架構

### 4.1 主導覽層級

`個人資產` 應從目前的 `復盤` 功能中獨立出來，成為主導覽的一級入口，而不是 `Review` 底下的其中一個分頁。

建議主導覽結構為：

1. `總覽`
2. `終端`
3. `籌碼`
4. `復盤`
5. `個人資產`
6. `設定`

對應原則：

- `復盤` 專注於 `交易日誌 + 回測`
- `個人資產` 專注於 `資產現值 + 持倉 + 現金流 + 對帳 + 維護`

這個調整的目的不是單純搬位置，而是明確切開兩種不同工作流：

- `復盤`：盤後檢討交易決策
- `個人資產`：日常查看資產變化與維護帳務

實作層級建議：

- 新增獨立 route，例如 ` /assets/:ticker? `
- 從 `Review` 頁籤與 navbar 的 review switch 中移除 `資產追蹤`
- 在主導覽列新增 `個人資產`

### 4.2 個人資產內部資訊架構

建議將現有資產追蹤頁重構為三個主頁籤：

1. `總覽`
2. `持倉與流水`
3. `資料維護`

這三頁應屬於同一個 `個人資產 workspace` 之下，以內部頁籤切換，不再掛在 `復盤` workspace 內。

## 5. 頁面一：總覽

### 5.1 頁面目的

讓使用者快速理解：

- 現在資產狀態
- 區間資產變化
- 變化來源拆解
- 影響最大的帳戶、市場、標的

### 5.2 頁面結構

#### 區塊 A：全域控制列

顯示：

- 日期區間切換：`7D / 30D / 90D / YTD / All`
- 基準幣別
- 最新估值時間
- 最新股價更新時間
- 最新匯率更新時間
- `重新估值` 按鈕

互動：

- 切換日期區間時，全頁卡片、圖表、排行榜同步更新
- 若有估值異常，於此列旁顯示 warning badge

#### 區塊 B：核心指標卡

顯示：

- 總資產現值
- 今日變化
- 本月變化
- 現金總額
- 持倉總市值
- 未實現損益
- 已實現損益
- 真實報酬率

呈現方式：

- 每張卡片除了主數字，還要有次要比較值
- 例如：`今日 +12,340 TWD`
- 次行顯示：`較昨日 +0.82%`

互動：

- 點擊卡片可切換主圖模式
- 例如點 `現金總額`，主圖改顯示現金曲線

#### 區塊 C：主資產曲線圖

這一塊應該是整頁主視覺，不再只用文字。

建議圖型：

- `總資產 / 純績效 / 現金 / 持倉市值` 多模式切換時間序列圖

顯示內容：

- 區間起點與終點
- 曲線高低點
- 游標日期對應的總資產、現金、持倉市值、淨流入

互動：

- Hover 顯示 crosshair 與 tooltip
- 點擊圖上某一天後，下方「變化拆解」與「貢獻排行」同步切換到該日期視角
- 支援拖曳縮放與重置區間
- 支援圖例切換顯示不同序列

技術建議：

- 使用 `lightweight-charts`

#### 區塊 D：變化拆解圖

這一區是總覽頁第二重要區塊，目的是回答「為什麼變」。

建議圖型：

- `資產變化瀑布圖`

拆解項目：

- 期初資產
- 入金
- 出金
- 股利 / 利息
- 手續費 / 稅 / 匯費
- 已實現損益
- 未實現損益
- 匯率影響
- 期末資產

互動：

- Hover 顯示該項金額與占比
- 點擊某個柱狀項目時，右側顯示對應事件清單
- 例如點 `股利`，旁邊列出區間內所有 dividend 現金事件

技術建議：

- 使用 `echarts`

#### 區塊 E：配置與貢獻區

分成三張互動圖卡：

- 帳戶配置圖
- 市場配置圖
- 損益貢獻排行

帳戶配置圖建議：

- `donut chart` 或 `treemap`

市場配置圖建議：

- `donut chart`

損益貢獻排行建議：

- `水平正負條圖`

互動：

- 點擊帳戶配置圖的某一塊，持倉預覽與最近流水同步過濾到該帳戶
- 點擊市場配置圖可切 `TW / US / 全部`
- 點擊某一檔貢獻排行，打開右側標的詳情抽屜

技術建議：

- 使用 `echarts`

#### 區塊 F：月度熱力圖

保留，但從靜態資訊升級成可互動區塊。

顯示：

- 每月真實報酬率
- 顏色深淺代表報酬強弱

互動：

- Hover 顯示當月起始資產、期末資產、淨流入、真實績效
- 點擊某個月份時，自動切換整頁日期區間為該月份

技術建議：

- 使用 `echarts` heatmap

#### 區塊 G：警示與快速預覽

顯示：

- quote gap
- 對帳差異
- 異常集中度
- 負現金
- 匯率缺失

以及：

- 前 5 大持倉 preview
- 最近 5 筆交易
- 最近 5 筆現金事件

互動：

- 點擊 warning 可跳到 `資料維護` 的對應區塊
- 點擊 preview 列可跳到 `持倉與流水` 並帶入篩選條件

### 5.3 總覽頁不應直接放的內容

以下內容不建議保留在總覽首頁：

- 帳戶管理表單
- 手動交易表單
- 手動現金事件表單
- CSV 匯入
- Journal 匯入
- 手動價格覆蓋表單
- 手動 FX 表單
- 調整事件表單

## 6. 頁面二：持倉與流水

### 6.1 頁面目的

讓使用者查明細與回溯來源，回答：

- 我目前持有哪些部位
- 每個部位是怎麼形成的
- 最近做了哪些交易與現金動作

### 6.2 頁面結構

#### 區塊 A：篩選列

提供：

- 帳戶篩選
- 市場篩選
- 幣別篩選
- 僅看持有中
- 僅看獲利 / 虧損
- 搜尋 ticker / 名稱

#### 區塊 B：持倉表

欄位：

- ticker / 名稱
- 帳戶
- 數量
- 平均成本
- 最新價
- 市值
- 未實現損益
- 已實現損益
- 權重
- 報價狀態

互動：

- 可排序
- 點擊列後開啟標的詳情抽屜
- 可由總覽頁帶著篩選條件跳轉進來

#### 區塊 C：標的詳情抽屜

顯示：

- 成本結構
- 最新估值
- 報價來源
- 在不同帳戶的分布
- 最近交易流水
- 若有含息報酬、股利或特殊調整，也在此呈現

#### 區塊 D：流水時間軸

頁籤切換：

- 全部
- 交易
- 現金
- 股利
- 轉帳

每筆事件顯示：

- 日期時間
- 帳戶
- 類型
- 金額或數量
- 對資產的影響
- 是否可編輯

#### 區塊 E：帳戶摘要條

顯示：

- 各帳戶現金
- 各帳戶持倉市值
- 各帳戶總資產
- 是否列入總資產
- 是否存在對帳差異

## 7. 頁面三：資料維護

### 7.1 頁面目的

集中所有低頻但必要的輸入、匯入、校正與例外處理，不干擾總覽與查詢體驗。

### 7.2 呈現方式

建議做成：

- 左側功能清單
- 右側工作區

左側功能分組：

1. 帳戶管理
2. 手動新增交易
3. 手動新增現金事件
4. CSV 匯入
5. Journal 匯入
6. 對帳快照
7. 例外處理
8. 系統工具

### 7.3 各工作區說明

#### 帳戶管理

保留原因：

- 帳戶名稱、類型、排序、是否列入總資產，無法由報價或匯率自動推導

#### 手動新增交易

保留原因：

- 交易流水是核心真實來源
- 即使未來增加券商同步，也應保留手動補錄能力

#### 手動新增現金事件

保留原因：

- 入金、出金、股利、費用、轉帳等仍需由使用者提供

#### CSV / Journal 匯入

保留原因：

- 高頻或批量操作需要高效率輸入方式

#### 對帳快照

保留原因：

- 系統推導值仍需能與實際帳戶比對

#### 例外處理

包含：

- 手動價格覆蓋
- 手動 FX 覆蓋
- 調整事件

保留原則：

- 保留能力
- 下沉層級
- 平常收合

#### 系統工具

包含：

- 批次重算
- 重新估值
- 資料來源狀態檢查

- 變化拆解
- 帳戶配置
- 市場配置
- 損益貢獻排行
- 月度熱力圖
- 持倉表
- 最近交易
- 最近現金事件

### 8.2 應保留但移到資料維護

- 帳戶管理表單
- 手動現金事件表單
- 手動交易表單
- CSV 匯入
- Journal 匯入
- 對帳快照輸入
- 手動價格覆蓋
- 手動 FX 覆蓋

- 手動價格輸入

原則：

- `人工覆蓋` 為備援

- 手動交易
- 手動現金事件
- 對帳
- 調整事件

因為這些都屬於系統的真實來源或例外校正機制，不是純 UI 功能。

## 9. 總覽頁互動圖表設計

### 9.1 圖表原則

互動圖表的目標不是讓頁面更花，而是讓使用者能：

- 快速掃視
- 點擊探索
- 追蹤原因
- 直接跳到明細

### 9.2 建議圖表清單

1. `資產曲線圖`
   用於展示總資產、現金、持倉市值、純績效的時間變化

2. `資產變化瀑布圖`
   用於拆解期初到期末資產的構成變化

3. `帳戶配置 donut / treemap`
   用於展示資產在帳戶間的分布

4. `市場配置 donut`
   用於展示 TW / US / 其他市場占比

5. `貢獻排行條圖`
   用於展示正負貢獻最大的標的

6. `月度熱力圖`
   用於展示每月真實績效分布

### 9.3 統一互動規格

所有圖表建議統一支援：

- hover tooltip
- click drilldown
- click 後帶出篩選
- empty state
- loading skeleton
- error state

### 9.4 互動後的頁面聯動

建議建立 cross-filter 體驗：

- 點擊帳戶配置圖 -> 持倉預覽與流水只看該帳戶
- 點擊市場配置圖 -> 持倉表切到該市場
- 點擊資產曲線某日期 -> 變化拆解切到該日區間
- 點擊貢獻排行某標的 -> 開標的詳情抽屜
- 點擊月度熱力圖 -> 日期區間切到該月份

這樣總覽就不只是展示板，而是真正能導航到明細的互動工作台。

目前前端已安裝：

- `echarts`
  用於瀑布圖、donut、treemap、heatmap、水平條圖

### 10.2 元件切分建議

建議拆成：

- warning 跳轉到資料維護指定區塊

## 12. 最終設計結論

資產追蹤模組不應再是「很多表單加上一些數字」的頁面，而應改成：

- `總覽`：用互動圖表講清楚資產如何變化
- `持倉與流水`：讓使用者追查細節與來源
- `資料維護`：集中低頻設定、匯入與例外修正

對於可自動取得的資料，應採用：

- `自動顯示`
- `手動覆蓋作為備援`

而不是讓人工輸入與自動估值並列在第一層頁面中。

這樣才能同時提升：

- 日常查看效率
- 對資產變化的理解速度
- 頁面專業感
- 使用者黏著度
